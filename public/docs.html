Quick start

curl -X POST https://YOUR-DOMAIN/v1/signup -H "Content-Type: application/json" -d '{"email":"you@company.com"}'
# → {"api_key":"df_live_…","plan":"free",…}

curl --fail-with-body -X POST https://YOUR-DOMAIN/v1/render \
  -H "Authorization: Bearer df_live_…" -H "Content-Type: application/json" \
  -d '{"template_id":"gallery:receipt"}' -o receipt.pdf

Without data, a gallery template renders its sample data and the response carries X-DocForge-Sample-Data: true.

Node.js

const res = await fetch('https://YOUR-DOMAIN/v1/render', {
  method: 'POST',
  headers: { Authorization: `Bearer ${process.env.DOCFORGE_KEY}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({ template_id: 'tpl_abc123', data: order }),
});
if (!res.ok) throw new Error(`DocForge ${res.status}: ${await res.text()}`);
const pdf = Buffer.from(await res.arrayBuffer());

Python

import requests
r = requests.post("https://YOUR-DOMAIN/v1/render",
    headers={"Authorization": f"Bearer {KEY}"},
    json={"template_id": "gallery:invoice", "data": invoice},
    timeout=30)
r.raise_for_status()
open("invoice.pdf", "wb").write(r.content)

PHP / Laravel

Render an existing Blade view. raw: true skips Handlebars (Blade already filled it in) and base_url resolves relative asset paths against your https site.

use Illuminate\Support\Facades\Http;

$base = 'https://YOUR-DOMAIN';
$pdf = Http::withToken(config('services.docforge.key'))
    ->post($base.'/v1/render', [
        'html' => view('pdf.invoice', $data)->render(),
        'raw' => true,
        'base_url' => url('/'),
    ])
    ->throw()
    ->body();

return response($pdf, 200, ['Content-Type' => 'application/pdf']);

POST /v1/render

FieldDescription
template_idA stored template (tpl_…) or a gallery template (gallery:invoice, gallery:receipt, gallery:certificate, gallery:quote, gallery:packing-slip). Required unless you send html.
html, cssInline Handlebars template, instead of template_id. css is also run through Handlebars but is not HTML-escaped, so never put untrusted values into CSS.
dataAn object, or a JSON-encoded string of one (handy when a no-code tool only gives you text). Defaults to the template's sample data, flagged with the X-DocForge-Sample-Data: true response header.
rawBoolean, inline html only. Skips Handlebars and renders the HTML as-is, for HTML you already built (Blade, Jinja, React SSR).
base_urlhttps:// only. Relative src/href in your HTML resolve against it. See Remote assets.
filenameUsed in Content-Disposition and in output: "url" links.
output"binary" (default, PDF body), "base64" (JSON {filename, content_type, size, base64}) or "url" (JSON {url, filename, size, expires_at, content_type}; the link is https://YOUR-DOMAIN/f/<token>/<filename>, needs no auth and expires after 24 hours). "url" is the easiest output for Zapier, Make, n8n and Bubble.
options.formatCase-insensitive: A4 (default), Letter, Legal, A5, A3, Tabloid, Ledger.
options.width, options.heightCustom page size as CSS lengths (e.g. "100mm"), instead of format.

options.margin{top,right,bottom,left} as CSS lengths. Default when absent: 14mm / 12mm / 16mm / 12mm. Use 0 for full-bleed (the certificate does).
options.preferCSSPageSizeBoolean. Lets @page { size: … } in your CSS win over format.

Response headers: X-Renders-Limit, X-Renders-Remaining, and while you are in the grace band X-Quota-Warning: over_limit plus X-Upgrade-Url (see Billing & limits). X-DocForge-Blocked-Assets reports skipped remote assets (see Remote assets).

Non-Latin text and right-to-left

Noto fonts are preinstalled, including 'Noto Nastaliq Urdu', Arabic, CJK and Devanagari. For Urdu or Arabic, render a full document with <html lang="ur" dir="rtl"> and set font-family: 'Noto Nastaliq Urdu', serif. Inline your own font as a data: URI if you need a specific face.

GET /v1/templates/:idFetch one, including HTML.
PUT /v1/templates/:idUpdate any subset of fields.
DELETE /v1/templates/:idDelete.
GET /v1/galleryBuilt-in templates with sample data (no auth).

Template language

Templates are Handlebars: {{name}}, {{#each items}}…{{/each}}, {{#if paid}}…{{/if}}. Values in HTML are escaped; values in css are not. Built-in helpers:

{{money amount "eur" "de-DE"}}Currency formatting. Currency (upper-cased for you) and locale are optional. Amounts are major units; for Stripe-style cents use {{money (div amount_paid 100) currency}}.
{{date issued "long" "en-GB" "Asia/Karachi"}}
{{date issued "short" locale="en-US" tz="America/New_York"}}		Date formatting: short, medium (default), long, full. Accepts ISO strings, epoch milliseconds and epoch seconds (numbers below 1e12, as Stripe sends). "now" is the current time; a missing value prints nothing.
{{sum items "qty" "price"}}Sum of qty×price over a list. With one field, sums that field. A missing field counts as 1, so a line without qty counts once.
{{qr payment_url size=120}}QR code as inline SVG. size in px, 32–400, default 96.
add, sub, mul, div, percent, fixedArithmetic, e.g. {{money (mul qty price) ../currency}}.
eq, gt, default, upper, lower, incComparisons and string helpers. {{inc @index}} gives 1-based row numbers.

A data field named like a helper (e.g. date) is shadowed by the helper when written alone; use {{this.date}} to read the field.

JavaScript inside templates is disabled. Images, fonts and stylesheets load as described in Remote assets.

Errors

Errors are JSON: {"error":"<code>","message":"…"}. Branch on error, show message.

HTTPerrorMeaning
400invalid_data, invalid_base_url, invalid_option, missing_template, invalid_jsonFix the request; message names the field.
401unauthorizedMissing or invalid API key.
402quota_exceeded, template_limitPlan limit reached. The body includes upgrade_url (pricing page) and upgrade_urls ({starter?, pro?, business?}: direct checkout links for the plans above yours, already tied to your account).
403account_suspendedContact support.
404template_not_foundUnknown tpl_… id, or it belongs to another account.
409email_taken, already_subscribedSignup with an existing email (recover the key at /#recover), or checkout while already on a paid plan (the body has manage_url).
422template_error, template_too_expensive, too_many_pagesHandlebars syntax error (message points at the line); template took too long to fill in; PDF above your plan's page limit.
429rate_limited, concurrency_limit, demo_busyToo many requests, too many renders in flight for your plan, or the public demo is busy. Back off and retry.
503busyRender queue is full. Retry after the Retry-After header (5 seconds).
504render_timeoutThe page took longer than 30 seconds to render (usually slow remote assets).
500render_failedOur fault. Send us the request_id from the body.

What counts against your quota: failed requests are refunded, except render_timeout, too_many_pages and template_too_expensive, which did the full rendering work and count as one render.

Safe to retry automatically: 429, 503 and 500, with backoff. Do not retry 4xx validation errors unchanged.

Billing & limits

Live values from GET /v1/plans:

Free–––3120
Starter–––202200
Pro–––1003500

  • Free PDFs carry a small "Made with DocForge" footer; paid plans have none.
  • Grace band: paid plans keep rendering for an extra 10% of their monthly renders, so a busy day does not stop your invoices. While you are in it, responses carry X-Quota-Warning: over_limit and X-Upgrade-Url. After that you get 402 quota_exceeded. Free has no grace band.
  • Every render returns X-Renders-Limit (your monthly renders) and X-Renders-Remaining (never below 0). Usage resets on the 1st of each month (UTC).
  • Concurrency is per account; extra parallel requests get 429 concurrency_limit.
GET /v1/mePlan, status, usage this month, limits, renders_grace and upgrade_urls.
GET /v1/billing/checkout?plan=starter200 {checkout_url} tied to your account (starter, pro, business); 400 unknown_plan; 409 already_subscribed with manage_url.
GET /v1/plansPlans and limits (no auth).

Payments are handled by Lemon Squeezy. Manage or cancel your subscription there; plan changes apply to your key automatically. See the refund policy.

Keys

POST /v1/keys/rotateIssue a new key and revoke the old one immediately. Returns {api_key}.
POST /v1/keys/recover{"email":"you@company.com"} → always 202 {message}. If the account exists, we email a link to https://YOUR-DOMAIN/#recover=<token>, valid 30 minutes, single use.
POST /v1/keys/recover/confirm{"token":"…"} → 200 {api_key, message} (a new key; the old one stops working) or 400 invalid_token. The landing page does this for you.

We only store a SHA-256 hash of your key, so we cannot show it again. Lost it? Use key recovery.

Remote assets

  • Only https:// URLs load. http://, file:// and private, loopback and link-local networks (including cloud metadata addresses) are blocked, even via redirects or DNS.
  • Only images, fonts and stylesheets load. No scripts, iframes, objects or embeds.
  • Recommended: inline logos and fonts as data: URIs. They never fail, never slow a render, and make output deterministic.
  • Slow assets count toward the 30-second render deadline (504 render_timeout, which counts as a render).
  • Skipped assets do not fail the render. Binary responses carry X-DocForge-Blocked-Assets: <n> and X-DocForge-Blocked-Asset-Example: <url>; JSON outputs (base64, url) include warnings.blocked_assets. Check them in development so a missing logo does not go unnoticed.

Security & data

  • PDFs are rendered in memory and returned in the response. We do not keep your rendered documents or the data you send, except output: "url" files, which are deleted after 24 hours.
  • Stored: your email, a SHA-256 hash of your API key, your saved templates, monthly render counts and the signup source (how you found us).
  • Each render runs in a fresh browser context with JavaScript disabled, and remote requests go through the asset filter.
  • The account database is snapshotted daily.
  • Lemon Squeezy is the merchant of record: it handles payment details and sales tax; we never see your card.

No-code

Every recipe uses output: "url": DocForge returns a 24-hour public link that the tool can fetch or attach. Store your API key in the tool's secret/credential field, not in plain text.

Make: Stripe invoice paid → PDF receipt by Gmail

  1. Stripe › Watch events, event invoice.paid.
  2. HTTP › Make a request: URL https://YOUR-DOMAIN/v1/render, method POST, header Authorization: Bearer df_live_…, body type Raw, content type JSON, "Parse response" on. Body: 
    {
  "template_id": "gallery:receipt",
  "output": "url",
  "filename": "receipt-{{1.number}}.pdf",
  "data": {
    "merchant": "Your Company",
    "number": "{{1.number}}",
    "paid_at": {{1.status_transitions.paid_at}},
    "customer_email": "{{1.customer_email}}",
    "amount_paid": {{1.amount_paid}},
    "currency": "{{1.currency}}",
    "locale": "en-US",
    "lines": {{3.json}}
  }
}
    Module numbers in {{…}} are illustrative; pick the values from Make's mapping panel.
    Field mapping from the Stripe invoice:
    Stripe invoiceReceipt field
    numbernumber
    customer_emailcustomer_email
    amount_paid (cents)amount_paid (cents; the template divides by 100)
    currency (usd)currency (any case)
    status_transitions.paid_at (epoch seconds)paid_at
    lines.data[]: description, amount, quantitylines[]: description, amount (cents), quantity
    Build lines before this module (shown as module 3 here, between Stripe and HTTP): an Iterator over lines.data, an Array aggregator with description, amount and quantity, and JSON › Create JSON to turn the array into text. Alternatively build the whole data object with Create JSON and pass its text as "data"; a JSON-encoded string is accepted.
  3. HTTP › Get a file with URL {{2.data.url}}.
  4. Gmail › Send an email to {{1.customer_email}}, attachment = the file from step 3 (file name {{2.data.filename}}).

n8n: new order → PDF → email

WooCommerce Trigger (order.created) or Airtable Trigger → HTTP Request (POST, JSON body, Response Format File, so the PDF arrives as binary data) → Send Email with attachment data. Paste this into the n8n canvas, then set your key on the Header Auth credential (name Authorization, value Bearer df_live_…):

{
  "name": "DocForge invoice on new order",
  "nodes": [
    {
      "parameters": { "event": "order.created" },
      "name": "WooCommerce Trigger",
      "type": "n8n-nodes-base.wooCommerceTrigger",
      "typeVersion": 1,
      "position": [0, 0]
    },
    {
      "parameters": {
        "method": "POST",
        "url": "https://YOUR-DOMAIN/v1/render",
        "authentication": "genericCredentialType",
        "genericAuthType": "httpHeaderAuth",
        "sendBody": true,
        "specifyBody": "json",
        "jsonBody": "={{ JSON.stringify({ template_id: 'gallery:invoice', filename: 'invoice-' + $json.number + '.pdf', data: { number: String($json.number), issue_date: $json.date_created, currency: $json.currency, client: { name: $json.billing.first_name + ' ' + $json.billing.last_name, email: $json.billing.email }, items: $json.line_items.map(i => ({ description: i.name, qty: i.quantity, price: Number(i.price) })) } }) }}",
        "options": { "response": { "response": { "responseFormat": "file" } } }
      },
      "name": "DocForge render",
      "type": "n8n-nodes-base.httpRequest",
      "typeVersion": 4.2,
      "position": [240, 0]
    },
    {
      "parameters": {
        "fromEmail": "billing@yourshop.com",
        "toEmail": "={{ $('WooCommerce Trigger').item.json.billing.email }}",
        "subject": "=Your invoice {{ $('WooCommerce Trigger').item.json.number }}",
        "text": "Thanks for your order. Your invoice is attached.",
        "options": { "attachments": "data" }
      },
      "name": "Send Email",
      "type": "n8n-nodes-base.emailSend",
      "typeVersion": 2,
      "position": [480, 0]
    }
  ],
  "connections": {
    "WooCommerce Trigger": { "main": [[{ "node": "DocForge render", "type": "main", "index": 0 }]] },
    "DocForge render": { "main": [[{ "node": "Send Email", "type": "main", "index": 0 }]] }
  }
}

Field names follow the gallery:invoice sample (number, issue_date, client, items[].description/qty/price); GET /v1/gallery/invoice shows the full shape, including company and due_date. For Airtable, map record fields the same way.

Zapier

  1. Any trigger (new Stripe charge, new Typeform entry, new row in Google Sheets…).
  2. Webhooks by Zapier › POST: URL https://YOUR-DOMAIN/v1/render, Payload Type json, Data: template_id = gallery:receipt, output = url, and data__number, data__customer_email, … for fields (double underscores nest them under data). Headers: Authorization = Bearer df_live_….
  3. Gmail / Outlook Send Email: map the webhook step's url into the Attachments field. Zapier downloads the file from the link.

Bubble

  1. API Connector › Add another API, name it DocForge. Authentication: Private key in header, key name Authorization, value Bearer df_live_… (shared header, never sent to the browser).
  2. Add a call: POST https://YOUR-DOMAIN/v1/render, Use as: Action, body type JSON: 
    { "template_id": "<template_id>", "output": "url", "data": <data> }
    Make <data> a dynamic parameter holding JSON text (e.g. built with :format as text); untick "Private" so workflows can set it. Initialize the call once with sample values.
  3. In a workflow, run the DocForge action and use Result of step 1's url to open, store or email the PDF. The link lasts 24 hours, so save the file to Bubble storage if you need it longer.
