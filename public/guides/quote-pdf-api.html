Quote and estimate PDF API

Turn a quote in your CRM, booking tool or spreadsheet into a PDF the client can sign: POST it to gallery:quote.

Sales quote with validity date, acceptance signature block and page numbers. Each line has a bold name with a muted detail line, which suits trades, agencies and B2B sales where the client needs to see what is included.

Sample data

This is the template's built-in sample, loaded live from GET /v1/gallery/quote. Edit it here and press Try it to render it with the public demo (no key; demo PDFs carry a SAMPLE watermark).

sample.json (editable)
{
  "number": "Q-1007",
  "valid_until": "2026-11-30",
  "currency": "EUR",
  "locale": "en-IE",
  "company": {
    "name": "Brightline Builders",
    "email": "sales@brightline.eu"
  },
  "client": {
    "name": "Hotel Aurora"
  },
  "project": "Lobby renovation",
  "items": [
    {
      "name": "Demolition",
      "details": "Remove existing flooring and fixtures",
      "qty": 1,
      "rate": 3200
    },
    {
      "name": "Oak flooring",
      "details": "Supply and install, per m²",
      "qty": 140,
      "rate": 62
    }
  ]
}

Fields

FieldMeaning
number, valid_untilQuote number and expiry date.
currency, localeFor example EUR with en-IE, or PKR with ur-PK.
company {name, email}, client {name}, projectHeader and "Prepared for" line.
items [{name, details, qty, rate}]Line items; the estimated total is sum(qty × rate).

Render it with curl

With no data, the API renders the sample above and sets X-DocForge-Sample-Data: true, which is a quick way to check your key:

Sample data
curl https://YOUR-DOMAIN/v1/render \
  -H "Authorization: Bearer $DOCFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"template_id": "gallery:quote"}' \
  -o quote.pdf

With your own data, save the JSON above as sample.json and wrap it:

Your data
jq '{template_id: "gallery:quote", filename: "quote.pdf", data: .}' sample.json \
  | curl https://YOUR-DOMAIN/v1/render \
      -H "Authorization: Bearer $DOCFORGE_KEY" \
      -H "Content-Type: application/json" \
      --data-binary @- -o quote.pdf -D headers.txt
grep -i x-renders-remaining headers.txt

From quote to invoice

Quote items use name/details/qty/rate; the invoice uses description/qty/price. When the client accepts, map one to the other and render gallery:invoice:

const invoiceData = {
  number: 'INV-' + quote.number.slice(2),
  issue_date: new Date().toISOString().slice(0, 10),
  due_date: dueIn30Days,
  currency: quote.currency,
  locale: quote.locale,
  company: quote.company,
  client: quote.client,
  items: quote.items.map((i) => ({ description: `${i.name}: ${i.details}`, qty: i.qty, price: i.rate })),
};

Getting a link instead of a file

Add "output": "url" and the response is JSON: {url, filename, size, expires_at, content_type}. The link works for 24 hours without a key, which is what Zapier, Make and n8n need to attach the PDF to an email. "output": "base64" returns the file inline in JSON. See the no-code recipes.

Customising the layout

Copy the template into your account and edit it there; your app keeps sending only data:

curl https://YOUR-DOMAIN/v1/templates \
  -H "Authorization: Bearer $DOCFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"from_gallery": "quote", "name": "My quote"}'
# -> {"id": "...", "name": "...", "html": "...", "css": "...", ...}
# then render with {"template_id": "<that id>", "data": {...}}

Stored templates keep HTML, CSS and sample data. Page options such as footer_html or landscape travel with each render request in options. Helpers are listed in the template language docs.
