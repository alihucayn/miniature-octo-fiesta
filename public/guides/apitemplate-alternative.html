DocForge as a APITemplate.io alternative for invoice and receipt PDFs

APITemplate.io offers a visual editor and HTML templates for PDFs and images. If your team is developers, your documents are invoices, receipts and certificates, and you want a simple per-PDF price, DocForge covers that with a smaller, simpler API.

Where APITemplate.io is the better choice: if you need a visual template editor for non-developers, asynchronous jobs with webhooks for very large batches, or PDF merging, DocForge does not do that today. Where DocForge fits: developers sending invoices, receipts, certificates, quotes and packing slips who want a synchronous API, ready-made templates and a lower price per document.

Images

APITemplate.io also generates images (for example social cards). DocForge only produces PDFs. If you rely on image output, keep that part where it is.

Port your template

DocForge templates are Handlebars, not Liquid. Most templates port line by line with this map (Jinja-style {% for %}/{% if %} templates follow the same rules):

LiquidDocForge (Handlebars)
{{ customer.name }}{{customer.name}}
{% if paid %}…{% else %}…{% endif %}{{#if paid}}…{{else}}…{{/if}}
{% unless paid %}…{% endunless %}{{#unless paid}}…{{/unless}}
{% if status == "paid" %}{{#if (eq status "paid")}}
{% if total > 0 %}{{#if (gt total 0)}}
{% for item in items %}{{ item.price }}{% endfor %}{{#each items}}{{price}}{{/each}}
{{ currency }} inside a for loop{{../currency}} (one level up from the loop item)
{{ forloop.index }}{{inc @index}}
{% if forloop.first %}{{#if @first}}
{{ price | times: qty }}{{mul price qty}}
{{ a | plus: b }} / minus / divided_by{{add a b}} / {{sub a b}} / {{div a b}}
{{ total | round: 2 }}{{fixed total 2}}
{{ total | money }}{{money total currency locale}}
{{ issued_at | date: "%B %-d, %Y" }}{{date issued_at "long" locale}}
{{ name | upcase }} / downcase{{upper name}} / {{lower name}}
{{ note | default: "-" }}{{default note "-"}}
{{ trusted_html }} (Liquid prints raw){{{trusted_html}}} (Handlebars escapes {{ }}; triple braces print raw)
{% assign subtotal = ... %}No assignments: compute the value in your code and send it in data
{%- ... -%} (trim whitespace){{~ ... ~}}

Then store it once and render it by id. The test render below uses your sample_data, because no data is sent:

Store and test
# 1. Store the ported template (HTML and CSS as JSON strings)
jq -n --rawfile html invoice.hbs --rawfile css invoice.css \
  '{name: "Invoice", html: $html, css: $css, sample_data: {number: "INV-001", items: [{description: "Test", qty: 1, price: 10}]}}' \
  | curl https://YOUR-DOMAIN/v1/templates \
      -H "Authorization: Bearer $DOCFORGE_KEY" \
      -H "Content-Type: application/json" --data-binary @-
# -> {"id": "tpl_...", "name": "Invoice", ...}

# 2. Render it with its sample data
curl https://YOUR-DOMAIN/v1/render \
  -H "Authorization: Bearer $DOCFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"template_id": "<id from step 1>"}' -o test.pdf

A template error comes back as 422 template_error with the Handlebars message and does not use a render. PUT /v1/templates/<id> updates it in place. If you would rather keep templating in your own app, send the finished HTML with "html": "...", "raw": true instead.
