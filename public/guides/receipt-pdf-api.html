Receipt PDF API for payments and subscriptions

POST a payment as JSON with "template_id": "gallery:receipt" and email the customer a clean, branded PDF receipt.

Compact payment receipt. Accepts Stripe-style data: amount_paid and line amounts in minor units (cents). The field names follow Stripe's invoice object, so most of the mapping is a straight copy. If you are on Stripe, the Stripe invoice.paid guide has the full webhook handler.

Sample data

This is the template's built-in sample, loaded live from GET /v1/gallery/receipt. Edit it here and press Try it to render it with the public demo (no key; demo PDFs carry a SAMPLE watermark).

sample.json (editable)
{
  "merchant": "Bookly",
  "number": "R-88213",
  "paid_at": 1793268720,
  "customer_email": "jane@example.com",
  "currency": "usd",
  "locale": "en-US",
  "amount_paid": 2400,
  "lines": [
    {
      "description": "Pro plan (monthly)",
      "amount": 1200,
      "quantity": 1
    },
    {
      "description": "Extra seats",
      "amount": 1200,
      "quantity": 3
    }
  ],
  "payment_method": "Visa •••• 4242",
  "support_email": "help@bookly.app"
}

Fields

FieldMeaning
merchant, logo_urlYour business name and an optional https or data: logo.
numberReceipt or invoice number.
paid_atWhen it was paid. Epoch seconds (Stripe), epoch milliseconds or an ISO string.
customer_emailPrinted as "Billed to".
currency, localeLower-case Stripe currencies are fine; the money helper upper-cases them.
amount_paidTotal in minor units (cents): 2400 prints as $24.00.
lines [{description, amount, quantity}]Line totals in minor units; quantity above 1 prints "× n".
payment_method, support_emailFree text such as "Visa •••• 4242", and where customers can reply.

Zero-decimal currencies (JPY, KRW and others) have no cents, but the template divides every amount by 100. Multiply those amounts by 100 before sending, or copy the template and remove the div … 100.

Render it with curl

With no data, the API renders the sample above and sets X-DocForge-Sample-Data: true, which is a quick way to check your key:

Sample data
curl https://YOUR-DOMAIN/v1/render \
  -H "Authorization: Bearer $DOCFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"template_id": "gallery:receipt"}' \
  -o receipt.pdf

With your own data, save the JSON above as sample.json and wrap it:

Your data
jq '{template_id: "gallery:receipt", filename: "receipt.pdf", data: .}' sample.json \
  | curl https://YOUR-DOMAIN/v1/render \
      -H "Authorization: Bearer $DOCFORGE_KEY" \
      -H "Content-Type: application/json" \
      --data-binary @- -o receipt.pdf -D headers.txt
grep -i x-renders-remaining headers.txt

Getting a link instead of a file

Add "output": "url" and the response is JSON: {url, filename, size, expires_at, content_type}. The link works for 24 hours without a key, which is what Zapier, Make and n8n need to attach the PDF to an email. "output": "base64" returns the file inline in JSON. See the no-code recipes.

Customising the layout

Copy the template into your account and edit it there; your app keeps sending only data:

curl https://YOUR-DOMAIN/v1/templates \
  -H "Authorization: Bearer $DOCFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"from_gallery": "receipt", "name": "My receipt"}'
# -> {"id": "...", "name": "...", "html": "...", "css": "...", ...}
# then render with {"template_id": "<that id>", "data": {...}}

Stored templates keep HTML, CSS and sample data. Page options such as footer_html or landscape travel with each render request in options. Helpers are listed in the template language docs.
