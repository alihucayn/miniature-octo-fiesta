Laravel HTML to PDF: dompdf, Snappy, Browsershot or an API?

You already have a Blade view for the invoice. The question is which engine turns it into a PDF, and what that costs you in CSS support, server setup and maintenance.

The four options

Pick dompdf if your layout is simple tables and you never want an external dependency. Avoid starting new work on Snappy: the engine is unmaintained. Pick Browsershot if you control the servers and are happy to keep Chromium patched. Pick an API if you want Chrome-quality output from shared hosting, Laravel Vapor or a small VPS without running a browser.

Setup

# .env
DOCFORGE_URL=https://YOUR-DOMAIN
DOCFORGE_KEY=df_live_...
// config/services.php
'docforge' => [
    'url' => env('DOCFORGE_URL'),
    'key' => env('DOCFORGE_KEY'),
],

Render your Blade view

Send the HTML Blade already produced with "raw": true: DocForge skips its own Handlebars step, so {{ left in your markup is printed literally. base_url resolves relative links such as /images/logo.png and /build/assets/app.css.

app/Http/Controllers/InvoicePdfController.php
<?php

namespace App\Http\Controllers;

use App\Models\Invoice;
use Illuminate\Http\Client\ConnectionException;
use Illuminate\Http\Client\RequestException;
use Illuminate\Support\Facades\Http;
use Illuminate\Support\Facades\Log;

class InvoicePdfController extends Controller
{
    public function __invoke(Invoice $invoice)
    {
        $html = view('invoices.pdf', ['invoice' => $invoice])->render();

        try {
            $response = Http::withToken(config('services.docforge.key'))
                ->timeout(45)
                // Retry the temporary failures (429 concurrency_limit, 503 busy) twice.
                ->retry(3, 2000, fn ($e) => $e instanceof RequestException
                    && in_array($e->response->status(), [429, 503]), throw: false)
                ->post(config('services.docforge.url').'/v1/render', [
                    'html' => $html,
                    'raw' => true,
                    'base_url' => config('app.url'), // must be https
                    'filename' => "invoice-{$invoice->number}.pdf",
                    'options' => [
                        'format' => 'a4',
                        'footer_html' => '<div style="font-size:9px;width:100%;text-align:center">Page <span class="pageNumber"></span> of <span class="totalPages"></span></div>',
                    ],
                ]);
        } catch (ConnectionException $e) {
            report($e);
            abort(503, 'The PDF service is unreachable. Try again in a minute.');
        }

        if ($response->failed()) {
            Log::warning('DocForge render failed', [
                'status' => $response->status(),
                'error' => $response->json('error'),       // stable code, e.g. quota_exceeded
                'message' => $response->json('message'),
                'upgrade_url' => $response->json('upgrade_url'),
                'request_id' => $response->json('request_id'), // quote this to support on a 500
            ]);
            abort(match ($response->json('error')) {
                'quota_exceeded', 'busy', 'concurrency_limit' => 503,
                default => 500,
            }, 'Could not generate the PDF right now.');
        }

        if ($blocked = $response->header('X-DocForge-Blocked-Assets')) {
            Log::notice("DocForge blocked {$blocked} asset(s)", [
                'example' => $response->header('X-DocForge-Blocked-Asset-Example'),
            ]);
        }

        return response($response->body(), 200, [
            'Content-Type' => 'application/pdf',
            'Content-Disposition' => "inline; filename=\"invoice-{$invoice->number}.pdf\"",
        ]);
    }
}

Images, fonts and CSS

  • Assets are fetched only over https from public IP addresses, and only images, fonts and stylesheets. On http://localhost they are blocked, and the response header X-DocForge-Blocked-Assets tells you how many. In local development, inline the CSS in a <style> tag and use data: URIs for the logo.
  • JavaScript does not run. Draw charts server-side as SVG, or render them to an image first.
  • Use @page and break-inside: avoid in your print CSS; they work as in Chrome's print preview.

Details: remote assets and security.

Many PDFs? Queue them

Each plan renders a fixed number of PDFs in parallel; extra requests get 429 concurrency_limit. Dispatch a queued job per document, store the result with Storage::put("invoices/{$invoice->number}.pdf", $response->body()), and set the queue's worker count to your plan's parallel-render limit.

Or move the template server-side

If you would rather send only data, store a Handlebars template once with POST /v1/templates (or start from gallery:invoice) and post ['template_id' => '...', 'data' => $invoice->toArray()]. Blade's {{ $x }} becomes {{x}} and @foreach becomes {{#each}}.
