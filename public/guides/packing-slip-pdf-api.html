Packing slip PDF API

Print a packing slip for every order: POST the order to gallery:packing-slip and send the PDF to the warehouse printer or the 3PL.

Warehouse packing slip with SKUs, quantities and a Shopify-style ship-to address. Rows are numbered, each has a ☐ to tick when packed, and the slip ends with a total unit count.

Mapping a Shopify order

From an orders/create or orders/paid webhook payload (REST field names):

const slip = {
  order_number: order.name,                       // "#1001"
  order_date: order.created_at,
  locale: 'en-US',
  shipping_method: order.shipping_lines?.[0]?.title ?? '',
  ship_to: {
    name: order.shipping_address.name,
    line1: order.shipping_address.address1,
    line2: order.shipping_address.address2,
    city: order.shipping_address.city,
    province: order.shipping_address.province,
    zip: order.shipping_address.zip,
    country: order.shipping_address.country,
  },
  items: order.line_items
    .filter((li) => li.requires_shipping)
    .map((li) => ({ sku: li.sku, name: li.name, qty: li.quantity })),
};

WooCommerce is similar: number, date_created, shipping.{first_name, last_name, address_1, address_2, city, state, postcode, country} and line_items[].{sku, name, quantity}.

Render it with curl

With no data, the API renders the sample above and sets X-DocForge-Sample-Data: true, which is a quick way to check your key:

Sample data
curl https://YOUR-DOMAIN/v1/render \
  -H "Authorization: Bearer $DOCFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"template_id": "gallery:packing-slip"}' \
  -o packing-slip.pdf

With your own data, save the JSON above as sample.json and wrap it:

Your data
jq '{template_id: "gallery:packing-slip", filename: "packing-slip.pdf", data: .}' sample.json \
  | curl https://YOUR-DOMAIN/v1/render \
      -H "Authorization: Bearer $DOCFORGE_KEY" \
      -H "Content-Type: application/json" \
      --data-binary @- -o packing-slip.pdf -D headers.txt
grep -i x-renders-remaining headers.txt

Getting a link instead of a file

Add "output": "url" and the response is JSON: {url, filename, size, expires_at, content_type}. The link works for 24 hours without a key, which is what Zapier, Make and n8n need to attach the PDF to an email. "output": "base64" returns the file inline in JSON. See the no-code recipes.

Customising the layout

Copy the template into your account and edit it there; your app keeps sending only data:

curl https://YOUR-DOMAIN/v1/templates \
  -H "Authorization: Bearer $DOCFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"from_gallery": "packing-slip", "name": "My packing slip"}'
# -> {"id": "...", "name": "...", "html": "...", "css": "...", ...}
# then render with {"template_id": "<that id>", "data": {...}}

Stored templates keep HTML, CSS and sample data. Page options such as footer_html or landscape travel with each render request in options. Helpers are listed in the template language docs.
